What the server sees

The widget's events: the sealed challenge (opaque to the browser), the proof-of-work size, and the signed pass token. A site's backend sends the token to POST /api/v1/siteverify with its secret key; a static page cannot, because it holds no secret.

    Settings

    Settings travel in the address, e.g. ?api=http://localhost:8080&sitekey=example-sitekey-0001&lang=en. The API must list this page's origin in the site's hostnames.

    Embed it

    <script src="https://captcha.example.org/widget.js" async defer></script>
<form method="post" action="/comment">
  <div class="belarusian-captcha" data-sitekey="your-site-key"></div>
  <button>Send</button>
</form>

    Your backend then checks the hidden bc-response field with POST /api/v1/siteverify. Run the API yourself with the Docker image; see the README and the design.
